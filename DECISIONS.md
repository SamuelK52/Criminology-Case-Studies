# Decisions

Simplest reasonable choices made where the brief was unclear, and changes the owner asked for. Where this file and `docs/BRIEF.md` disagree, this file wins.

| # | Date | Decision | Why |
|---|---|---|---|
| 1 | 2026-11-06 | Project lives in `C:\Users\Samuel\dev\caselab`, outside OneDrive. | OneDrive syncing `node_modules` causes slow installs and `EPERM` file-lock errors. GitHub is the backup. |
| 2 | 2026-11-06 | Next.js 16.4 rather than 14. | The brief says "14+", and `create-next-app` installs 16. Cache Components is on, so request-time data (database, cookies) sits behind `<Suspense>` and `connection()`. |
| 3 | 2026-11-06 | `cases` has both `original_verdict` and `latest_outcome`. The prototype's single outcome text is seeded into `latest_outcome`, word for word, and `original_verdict` starts empty for lecturers to fill in. | The accuracy NFR says the two are always shown separately, but the seed has only one field, and case facts must not be rewritten. |
| 4 | 2026-11-06 | Sign-up offers Student, Study group and Lecturer. Lecturer is a *request* (`requested_role`) that the builder approves. Builder is set only by `npm run db:setup -- --builder email`. | Otherwise anyone could self-assign a role that edits the shared case bank. |
| 5 | 2026-11-06 | Signed-out visitors can read the **shared** case bank only. | The case facts are public, and the list must show before sign-in. Notes, resources, progress and class cases need sign-in. |
| 6 | 2026-11-06 | The prototype's 4 auto-made flashcards per case (`seedCards`) are stored as `derived` rows, rebuilt by a trigger when a case changes. Case 16's 7 EXTRA cards are `seed` rows (slots 1–7) and come first. | A lecturer's correction then reaches the cards, and students keep their spaced-repetition progress because card IDs don't change. |
| 7 | 2026-11-06 | The seed quiz is built at runtime from the case bank (as in the prototype). Nothing is stored. | It shuffles distractors from other cases each time. |
| 8 | 2026-11-06 | The PDPA guard is enforced in **both** the UI (`src/lib/pii.ts`) and the database (`has_pii()` check constraints). Boundaries are "not a digit", so a 17-digit number isn't flagged. A test checks that both agree. | The brief wants a clear message in the UI. The database stops a bypass. |
| 9 | 2026-11-06 | The AI rate limit (20 per user per rolling hour) is a Postgres function `ai_take_token()` that checks and records in one locked step. | No Redis needed, and it works with any number of app instances. |
| 10 | 2026-11-06 | A user's own case may not reuse a shared-bank case name, and user cases get codes `U1`, `U2`, … | Matches the prototype's duplicate check ("That case is already in the list.") and "U" ids. |
| 11 | 2026-11-06 | Lecturers can edit shared-bank cases (needed for FR-13: "Lecturer edits case 10") and cases in classes they teach, but can't change owner/code/class or delete cases they don't own. | Matches the role matrix: lecturers correct cases, but can't delete. |
| 12 | 2026-11-06 | Study-group members can save their own flashcard progress and quiz scores, but can't reset progress or write anything else. | The brief says they "flip flashcards, take quizzes and see their own progress", and the prototype locks Reset for them. |
| 13 | 2026-11-06 | DB tests use PGlite (Postgres in WebAssembly) and run as the real `caselab_app` role. | No Docker on this machine. PGlite runs the real migrations in real Postgres. |
| 14 | 2026-11-06 | Hosting is **Railway** instead of Vercel, at the owner's request. Railway project: `caselab` in "Goon Monster's Projects", with services `Postgres` and `web` (from GitHub `SamuelK52/Criminology-Case-Studies`, `main`). Live at https://web-production-8e46.up.railway.app. Railway is retiring `railway.json` on 2026-12-01, so the deploy config is now Infrastructure-as-Code in `.railway/railway.ts`, generated by `railway config migrate --variables unmanaged`. `unmanaged` keeps secrets in the Railway dashboard, never in the repo. | The owner asked to link the project to their Railway account. |
| 15 | 2026-11-06 | **Plain PostgreSQL instead of Supabase**, at the owner's request (Railway Postgres in production). The schema is self-contained: own `users` and `sessions` tables, `current_user_id()` instead of Supabase's `auth.uid()`. The app talks to Postgres directly with `postgres` (postgres.js); there is no REST layer. | The owner asked for Postgres, not Supabase. |
| 16 | 2026-11-06 | **RLS without Supabase:** the app logs in as `caselab_app` (no superuser, no `BYPASSRLS`, doesn't own tables). Each request is one transaction that first sets `app.user_id`. The app builds its runtime URL from `DATABASE_URL`'s host and `APP_DB_PASSWORD`, so it never connects with the owner login. | It keeps the brief's rule: "enforce in the database with RLS, not only in the UI". **Trade-off:** with Supabase, the user id came from a signed JWT. Here the server sets it after checking the session cookie. RLS still catches bugs in app logic and UI bypasses, but it trusts the server code to set the right id. |
| 17 | 2026-11-06 | **Own email + password auth** (Milestone 2): scrypt password hashes (Node's built-in `crypto`, no native modules), random session tokens in an httpOnly, Secure, SameSite=Lax cookie, stored only as SHA-256 hashes, with a 30-day expiry. The app role can only reach credentials through `create_user`, `get_login`, `create_session`, `resolve_session` and `delete_session`. | It replaces Supabase Auth with the fewest moving parts, and nothing new is needed on Railway. |
| 18 | 2026-11-06 | Migrations are tracked in `schema_migrations` and applied once each by `scripts/db-setup.mjs`. Railway runs it as the **pre-deploy** command. The seed is idempotent and runs every time. | Deploys apply new migrations without anyone pasting SQL by hand. |
| 19 | 2026-11-06 | The pre-deploy step also re-applies `APP_DB_PASSWORD` to the `caselab_app` role on every deploy. If two deploys overlap (for example, a variable change right after a push), the older deploy's pre-deploy could in theory run last; `railway redeploy --service web` re-syncs. | Rotating the password is then just "change the variable", with no SQL by hand. |
| 20 | 2026-11-08 | **First-deploy failure, root cause:** the `web` service was created after Railway stopped applying `railway.json` to new services, so its `preDeployCommand` was `null`. The database stayed empty and `caselab_app` had no password, which caused `password authentication failed`. Fixed by `railway config apply` from `.railway/railway.ts`, which set the pre-deploy, start and build commands and the health check. `railway.json` was deleted because nothing reads it. Deploy settings now change only via `config plan` / `config apply`; editing the file and pushing does nothing on its own. `railway` (Railway's official TypeScript SDK, `railwayapp/railway-ts-sdk`) is a dev dependency so the CLI can evaluate the file. | Verified: deploy `93f0162d` ran the pre-deploy, and the live site lists all 16 cases from Railway Postgres. |
| 21 | 2026-11-09 | **Deploys on push run through GitHub Actions** (`.github/workflows/deploy.yml`), not Railway's GitHub app. Even after the app was installed and the source reconnected, a test push (`9e0736e`) started no deploy, and GitHub showed no Railway deployments or checks, so the app evidently had no access to this repo. The workflow runs the checks, then `railway redeploy --commit <sha>` with a production-only Railway **project token** (GitHub secret `RAILWAY_TOKEN`). It waits for `SUCCESS` and smoke-tests the live URL. A concurrency group serialises deploys (see #19). | It doesn't depend on the app's account permissions, broken code can't deploy, and the token is limited to one environment and can be revoked in Railway. |
| 22 | 2026-11-09 | The deploy workflow uses a Railway **workspace token** (GitHub secret `RAILWAY_API_TOKEN`) instead of a project token, at the owner's request. Every CLI call names the project, environment and service explicitly. | The owner couldn't find project tokens in the dashboard. **Trade-off:** this token can reach every project in "Goon Monster's Projects", not just caselab production. It's stored only as a GitHub secret and can be revoked in Railway at any time. |
| 23 | 2026-11-09 | **Sign-in throttling:** after 10 failed passwords for one email within 15 minutes, sign-in for that email is refused until the window passes. Failures are kept in `login_failures`, which the app role can't read. The error never says whether an email exists, and unknown emails still run a full scrypt check so the timing doesn't reveal it either. | The brief asks for "real login" and rate-limits only AI. Without a limit, a password could be guessed online. A per-email limit needs no extra infrastructure. |
| 24 | 2026-11-09 | Milestone 2 shows a **"Your access" card** on the home page listing what the role can and can't do (FR-09). Real Add/Edit/Delete/AI controls are added, and hidden by role through `can()` in `src/lib/permissions.ts`, as Milestones 3–7 build them. | Case tools don't exist yet, so FR-09 can't be shown by hiding them. The card makes the role matrix visible and testable now. |
| 25 | 2026-11-09 | Queries return the `app_role` enum cast to `text`. `DB_POOL_MAX` (default 10) sets the pool size. | Local checks run Postgres through PGlite's socket server, which hangs when a result contains an enum column, and shares one session across connections (so it needs a pool of 1). The cast changes nothing on real Postgres. |
| 26 | 2026-11-09 | **AI requests:** `@anthropic-ai/sdk`, model `claude-sonnet-5-5` (from the approved plan; `ANTHROPIC_MODEL` overrides it), effort `medium`, streamed. Requests opt into server-side refusal fallback (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`): if Claude declines, the API retries on another model instead of returning nothing. A final refusal shows a plain message. The route waits for the first chunk, so a rejected request returns a clear error, not an empty answer. | Summaries need care, not deep reasoning, so `medium` keeps answers fast and cheaper. The fallback is Anthropic's recommended default for this model. |
| 27 | 2026-11-09 | **Case pages are `/cases/<code>`** (e.g. `/cases/07`, `/cases/U1`), and `/` redirects to `/cases/01` in `next.config.ts`. Folder tabs are shown only once each tab exists (Summary now; Resources, Flashcards, Quiz, Arguments, Progress and Features in Milestones 4–7). Search filters the drawer in the browser over the cases the user can see. | Links can be shared and bookmarked, and no dead tabs are shown. |
| 28 | 2026-11-09 | **Notes autosave** 0.8 s after typing stops (one note per user per case, upserted). A note that looks like an IC or card number is **not saved**, and the status line says so (as in the prototype). Study-group accounts don't see the notes or AI card (FR-09). A new own case is marked "verify latest outcome". | Matches the prototype's behaviour, with the data in Postgres instead of the browser. |
| 29 | 2026-11-09 | Railway health-checks **`/api/health`** (200 when the app can query Postgres as `caselab_app`, otherwise 503) instead of `/`. Applied with `railway config apply`. | The first Milestone 3 deploy failed: `/` now answers with a 307 redirect to `/cases/01`, and the health check accepts only 200. The old release stayed live, so nothing broke for users. |
| 30 | 2026-11-09 | **Removing a resource is gated on the "edit" permission, not "del".** A lecturer's "del" is off in the role table because they can't delete students' work, but they must be able to remove their own and their class's shared resources. RLS still only allows removing your own (or, for the builder, any). | Keeps the role table's meaning without locking lecturers out of their own material. |
| 31 | 2026-11-09 | **Each folder tab is its own URL** (`/cases/07`, `/cases/07/resources`, …), drawn by a shared frame. Switching case in the drawer stays on the same tab. Tabs are links with `aria-current="page"`, not ARIA tabs, because each one loads a page. | Tabs can be bookmarked and reloaded, and each tab only loads its own data. |
| 32 | 2026-11-09 | **Shared resources:** lecturers pick "Share with <class>" for classes they teach; the builder can also pick "Share with everyone" (all signed-in users). Study-group members see shared resources with every control hidden. Signed-out visitors see none. | Matches the brief ("lecturer creates and corrects cases and shared resources for a class") and the existing RLS policies. |
| 33 | 2026-11-09 | **Source suggestions:** "Suggest what to look up" uses the prototype's prompt word for word and the same 20-per-hour AI limit. When AI is offline or not available to the role, the card shows the prototype's built-in text instead. The AI routes now share one module (`src/lib/ai/respond.ts`) and one client hook (`useAiStream`). | No invented citations (prompt + RULES); later AI tools (flashcards, quiz, arguments) reuse the same checks and streaming. |
| 34 | 2026-11-09 | **AI flashcards and quizzes keep the prototype's prompts** ("Return JSON array of …") and the reply is parsed leniently: the first `[` to the last `]`, then every card/question is checked (lengths, PII, the answer must be one of the options). Unusable output returns a clear "try again" message. They use the same 20-per-hour limit and the same streamed request as the other AI tools. | The brief asks for the prototype's wording; checking the output protects the deck and quiz from malformed or unsafe items. |
| 35 | 2026-11-09 | **Generating AI cards replaces your earlier AI cards for that case** (their progress goes with them); built-in cards and their progress are untouched. | Matches the prototype (`cards=[...seedCards(cur),...r]`) and stops the deck growing by 8 every click. |
| 36 | 2026-11-09 | **Quiz scores are counted in the browser** and the server only checks they are whole numbers with 0 ≤ score ≤ total ≤ 20 (also a database constraint). | AI quizzes aren't stored, so the server can't re-mark them. A student could only inflate their own private score. |
| 37 | 2026-11-09 | **Signed-out visitors can flip flashcards and take the built-in quiz**; nothing is saved and the page says to sign in to keep progress. | Helps the "flip a first flashcard within 30 seconds" usability target and shows the app before sign-up. |
| 38 | 2026-11-10 | **The Arguments tab is AI-only**, as in the prototype: with AI off it shows a plain message and the buttons are disabled; study group sees a note instead of the tools. One route (`/api/ai/arguments`) serves ladder, mock-trial notes and counter-check, each counted against the same 20-per-hour limit. The counter-check point is limited to 500 characters and refused if it contains an IC or card number. | The brief requires copying the prototype's prompts, and the prototype has no built-in ladders; writing ladders by hand would risk stating unverified arguments as fact. |
| 39 | 2026-11-11 | **Progress and Features are folder tabs inside the case frame** (`/cases/<code>/progress`, `/cases/<code>/features`), like the prototype, even though they cover every case. | Keeps the prototype's seven folder tabs and the case drawer in one place. |
| 40 | 2026-11-11 | **Backups are a new JSON format (`caselab: 2`)** that references cases by id and code; the prototype's localStorage dump (`caselab: 1`) is refused with a clear message. Import **merges and never deletes**: a note is restored when missing, emptied (clearing the box saves an empty note) or older than the backup's copy; resources, AI cards and quiz scores are skipped if already present; card progress keeps the newer record; own cases are re-created (with a new U-code) if missing. It runs as the user in one transaction, so RLS and the PII checks apply and a refused item cancels the whole import. Export covers only the user's own data. | FR-12 asks for "export, delete one note, import, and the note is back"; merging makes a restore safe to repeat and never loses newer work. |
| 41 | 2026-11-11 | **Import is a route handler (`POST /api/import`)**, not a server action, because backups can exceed server actions' 1 MB body limit (capped at 2 MB here). It also rejects cross-site `Origin` headers, on top of the SameSite=Lax session cookie. Export/import follow the role table's "Backup/export" column: students and the builder. | Larger backups work, and the endpoint can't be driven from another site. |
